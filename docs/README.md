# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Docs. This guide provides a quick overview of how OctoAcme approaches project delivery and helps teams navigate the supporting process documents.

## Quick Overview

OctoAcme follows a structured, iterative project management approach grounded in customer value, clear ownership, data-informed decisions, and psychological safety. Projects move through a predictable lifecycle from initiation to retrospective, with defined roles, artifacts, and communication rhythms.

## Project Lifecycle Overview

1. **Initiation** — Validate the business need, align stakeholders, and create the project one-pager.
2. **Planning** — Break the work into shippable increments, define dependencies, and establish timelines.
3. **Execution & Tracking** — Build, test, review, and track progress with the project board and team rituals.
4. **Release & Deployment** — Deliver changes with validation, rollback readiness, and stakeholder communication.
5. **Retrospective & Continuous Improvement** — Capture lessons learned and turn them into action items.

## Core Roles

- **Project Manager (PM)** — Coordinates delivery, schedules, risks, and communications.
- **Product Manager (PdM)** — Defines outcomes, prioritizes backlog, and measures success.
- **Developers** — Implement features, collaborate on design, and contribute to testing.
- **QA / Testing** — Validate quality, acceptance criteria, and release readiness.
- **Stakeholders** — Provide inputs, approvals, and strategic alignment.

## Key Principles

- **Customer-first** — Prioritize customer value and usability.
- **Iterative delivery** — Deliver small, testable increments.
- **Clear ownership** — Each project has a named PM and Product Lead.
- **Data-informed decisions** — Measure impact and iterate based on evidence.
- **Psychological safety** — Encourage feedback, learning, and candid communication.

## Communication Cadence

- Weekly sync between PM and PdM
- Twice-weekly standups for the delivery team (or as agreed)
- Monthly stakeholder updates
- Ad-hoc escalations as needed

## Using These Docs

- Keep the project charter or one-pager updated in the project repo.
- Add process-specific documentation to `.copilot/` if you want Copilot Spaces to use them as context.
- Reference the relevant document during initiation, planning, execution, and release activities.
- Use the included checklists to validate completion of key milestones and process steps.

## Common Project Artifacts

Across OctoAcme workflows, teams typically use the following artifacts:

- Project one-pager or charter
- Prioritized backlog and acceptance criteria
- Risk register and dependency log
- Project board and status dashboards
- Release notes and rollback plan
- Retrospective notes and action items
